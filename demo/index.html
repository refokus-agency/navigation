Manual test — accessible dropdown + navbar scroll animation

This page loads the real dist/navigation.browser.js build. The package ships no CSS; every animation here is plain CSS keyed off the [data-state] and [data-motion] hooks the library sets.

Pointer

  • ☐ Hover a trigger → opens after 200 ms
  • ☐ Hover a sibling within ~300 ms of closing → switches instantly, and the panel slides from the correct side
  • ☐ Wait >300 ms, then hover → pays the 200 ms delay again
  • ☐ Move onto the panel → stays open; leave → closes after 150 ms
  • ☐ Panel resizes smoothly between Products / Solutions / Developers
  • ☐ Click a trigger → toggles. After click-to-close, hovering the same trigger does nothing until you leave and re-enter
  • ☐ Click a link inside a panel → closes. ⌘/Ctrl-click → stays open
  • ☐ Click anywhere outside the nav → closes

Keyboard — Tab is the primary path

Click the page background first, then Tab in from the top.

  • ☐ Tab reaches Products; panel stays closed (no auto-open)
  • ☐ Enter opens it
  • ☐ Tab now steps into the panel → Analytics
  • ☐ Keep tabbing: Automation → Reporting
  • ☐ Tab off the last link → panel closes and focus lands on Solutions
  • ☐ Enter on Solutions, tab through all 6 links, Tab off the end → Developers
  • ☐ From Developers' last link, Tab → Pricing (the plain link, not skipped)
  • ☐ From Pricing, Tab → leaves the nav into the page
  • ☐ Shift+Tab on a panel's first link → back to its trigger, panel stays open
  • ☐ Shift+Tab again → panel closes, focus on the previous trigger
  • ☐ With everything closed, tabbing past the nav takes 4 stops, not 20
  • ☐ Esc from inside a panel closes it and returns focus to the trigger
  • ☐ After Esc, hover on that same trigger stays closed until you leave and re-enter

Keyboard — arrows (secondary, triggers only)

  • ☐ ← → on a trigger cycle the triggers and wrap
  • ☐ ↓ on an open trigger moves into the panel's first link
  • ☐ Home / End jump to first / last trigger
  • ☐ Focus a link inside a panel and press the arrows / Home / End → the nav must ignore them
  • ☐ Same in the search field below — typing and arrowing must not move focus out

Screen reader / a11y

  • ☐ Inspect a trigger: aria-expanded flips, aria-controls points at the panel id
  • ☐ Panel has role="region" and aria-labelledby
  • ☐ Pricing is a plain link — it must have no aria-expanded

Mobile (resize below 767px)

  • ☐ Root gets data-nav-mode="mobile"; hover no longer opens anything
  • ☐ Tap ☰ then a trigger → panel opens on tap
  • ☐ ← Back closes the panel but leaves the burger menu open
  • ☐ Close the burger with a panel open, reopen → starts on the main list
  • ☐ Cross the 767px line with a panel open → it closes

Navbar scroll animation

  • ☐ Nav slides down on load
  • ☐ Scroll down >50px → hides; scroll up → shows
  • ☐ Scroll down so the nav hides, then Shift+Tab back up into it → the nav slides back into view (was: focus landed off-screen)
  • ☐ Same with the browser's find-and-focus or clicking a skip link

Open/close must look identical by pointer and keyboard

  • ☐ Enter to open, Esc, then Enter again immediately → the panel appears at its full height at once
  • ☐ Hammer Enter / Esc repeatedly → no slow height creep, no half-sized panel (was: reopening during the exit animation animated the height from the stale value)
  • ☐ Compare against the mouse: hover open, move away, hover again → same look
  • ☐ Switching between panels still animates the height smoothly (that transition is intentional)
